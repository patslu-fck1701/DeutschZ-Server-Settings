=====================================================
  SprayZ - Quest Creation & Filter Guide
=====================================================

This file is auto-regenerated on every server start into:
  $profile:SprayZ/SprayZ_Quest_Guide.txt

Do not edit this file by hand — every server boot overwrites it.

It's split into two parts:
  PART 1 - SETUP WALKTHROUGH   How to wire an Expansion quest to a SprayZ filter
  PART 2 - FILTER REFERENCE    Every ActionType, parameter, and example


=====================================================
  OVERVIEW
=====================================================

SprayZ hooks into DayZ Expansion's Quest system via the ACTION
objective type (ObjectiveType 10). Expansion Quests is a SOFT DEPENDENCY —
if it's not loaded the quest system is compiled out and everything else works
normally. No errors.

An Expansion ACTION objective fires whenever a player performs a named
ScriptedUserAction. Our mod hooks that event and, if the objective has a
matching SprayZ filter entry, runs additional validation on top of Expansion's
built-in check. Only if all conditions pass does the objective tick up.

Expansion side handles: quest flow, NPC dialogue, rewards, progress tracking.
SprayZ side handles:       design matching, territory/time/weather/surface
                        conditions, sequence ordering, discovery logic.

The link between the two is the ObjectiveID. You create an Expansion objective
with an ID, then add an entry with the same ID to the
"QuestObjectiveFilters" array in SprayZ_Designs.json.

Simple quests (spray 5 graffiti anywhere, clean 3 graffiti) need only the
Expansion JSON files. The SprayZ filter is optional — leave it out and the
objective ticks on every qualifying action.


=====================================================
  IMPORTANT: QUEST DESIGN RULES
=====================================================

-- UNIVERSAL (all servers) --

1. Multi-stage objectives within one quest are fine.
   Use "SequentialObjectives": 1 on the Quest JSON to force them to be
   completed in order. This is different from chaining multiple quests via
   PreQuestIDs — this is one quest with multiple objectives.

2. Set "ActionNames" correctly on the objective:
      "SprayZ_ActionSprayGraffiti"   for spray_* and mark and discover_* types
      "SprayZ_ActionCleanGraffiti"   for clean type
   The SprayZ filter's ActionType field decides which validator runs — the
   ActionNames field is what Expansion listens on. Discover filters ride on
   the spray action because they trigger during inspect-through-spray flow.


-- PER-CHARACTER MODE ONLY --

The rules below apply ONLY if you have
    "CollectionPerCharacter": true
in SprayZ_Config.json. In the default per-player mode you can ignore this entire
section — quest chains work, and Repeatable is not required (each player only
needs to complete a given quest once, ever).

1. DO NOT chain design-unlock quests with PreQuestIDs.
   Make each quest standalone with "PreQuestIDs": []. Chains cause issues
   with per-character tracking because Expansion tracks quest progress by
   Steam UID, not character name — a new character would inherit the prior
   character's chain state.

2. Set "Repeatable": 1 on design-unlock quests.
   This lets new characters re-accept the quest after a fresh start. Our mod
   blocks re-acceptance on characters that already have the unlocks via
   Expansion_CanStartQuest, so players can't farm the rewards.

=====================================================
  STEP BY STEP: CREATING A QUEST
=====================================================

1. CREATE AN NPC (or reuse one)
   File: ExpansionMod/Quests/NPCs/QuestNPC_<ID>.json

   {
       "ConfigVersion": 6,
       "ID": <unique NPC ID>,
       "ClassName": "ExpansionQuestNPCGuo",
       "Position": [x, y, z],
       "Orientation": [yaw, 0, 0],
       "NPCName": "NPC Display Name",
       "DefaultNPCText": "What the NPC says when idle",
       "NPCLoadoutFile": "SurvivorLoadout",
       "NPCInteractionEmoteID": 1,
       "NPCQuestStartEmoteID": 58,
       "NPCQuestCompleteEmoteID": 39,
       "NPCQuestCancelEmoteID": 60,
       "NPCType": 0,
       "Active": 1
   }

   NPC class names are Expansion-provided:
     ExpansionQuestNPCMirek, ExpansionQuestNPCDenis, ExpansionQuestNPCBoris,
     ExpansionQuestNPCGuo, etc.


2. CREATE AN OBJECTIVE
   File: ExpansionMod/Quests/Objectives/Action/Objective_A_<ID>.json

   {
       "ConfigVersion": 28,
       "ID": <unique objective ID>,
       "ObjectiveType": 10,
       "ObjectiveText": "Description shown to the player",
       "TimeLimit": -1,
       "Active": 1,
       "ActionNames": ["SprayZ_ActionSprayGraffiti"],
       "AllowedClassNames": [],
       "ExcludedClassNames": [],
       "ExecutionAmount": <how many times>
   }

   ActionNames:
     "SprayZ_ActionSprayGraffiti"  for spray_*, mark, discover_* filters
     "SprayZ_ActionCleanGraffiti"  for clean filter

   Discover-family objectives use the spray action because inspection flows
   through the same UI path. Which validator runs is decided by the
   ActionType field in the SprayZ filter, not the ActionNames list.


3. CREATE THE QUEST
   File: ExpansionMod/Quests/Quests/Quest_<ID>.json

   {
       "ConfigVersion": 22,
       "ID": <unique quest ID>,
       "Type": 0,
       "Title": "Quest Title",
       "Descriptions": [
           "Text when accepting the quest",
           "Text while the quest is active",
           "Text when turning the quest in"
       ],
       "ObjectiveText": "Short objective summary",
       "QuestGiverIDs": [<NPC ID>],
       "QuestTurnInIDs": [<NPC ID>],
       "Objectives": [
           { "ConfigVersion": 28, "ID": <objective ID>, "ObjectiveType": 10 }
       ],
       "PreQuestIDs": [],
       "Repeatable": 1,
       "Autocomplete": 0,
       "IsGroupQuest": 0,
       "CancelQuestOnPlayerDeath": 0,
       "QuestItems": [],
       "Rewards": [
           { "ClassName": "SprayZ_GraffitiCan", "Amount": 1, "Attachments": [],
             "DamagePercent": 0, "HealthPercent": 0, "QuestID": -1, "Chance": 1.0 }
       ],
       "NeedToSelectReward": 0,
       "RandomReward": 0,
       "RandomRewardAmount": -1,
       "RewardsForGroupOwnerOnly": 1,
       "RewardBehavior": 0,
       "FollowUpQuest": -1,
       "PlayerNeedQuestItems": 0,
       "DeleteQuestItems": 0,
       "SequentialObjectives": 1,
       "IsAchievement": 0,
       "QuestColor": 0,
       "ReputationReward": 0,
       "ReputationRequirement": -1,
       (RequiredFaction, FactionReward, FactionReputationRequirements,
        FactionReputationRewards — leave these empty unless using factions)
       "SuppressQuestLogOnCompetion": 0,
       "Active": 1
   }

   See "QUEST DESIGN RULES" above for Repeatable and PreQuestIDs guidance —
   the defaults shown (Repeatable: 1, PreQuestIDs: []) are safe for both
   per-player and per-character servers.


4. (OPTIONAL) ADD SprayZ FILTER
   File: SprayZ/SprayZ_Designs.json

   Add an entry to the "QuestObjectiveFilters" array that references the
   same ID as the Expansion objective:

   {
       "ObjectiveID": <same ID as the Expansion objective>,
       "ActionType": "spray",
       ... additional filters ...
   }

   Skip this step entirely if the quest doesn't need any design, location,
   or environmental conditions.


=====================================================
  DESIGN LOCKING
=====================================================

SprayZ_Designs.json supports four overlapping ways to restrict which designs
players can see and use. All four are additive — you can mix them freely.


1. BlockedDesigns  (global removal, not a lock)
   Top-level array of design names. Listed designs are stripped from the
   server's catalogue entirely on startup — they don't appear in the picker,
   can't be sprayed, can't be discovered, and their Spraydex total drops
   accordingly. Applies to main mod AND pack-contributed designs.

   Use this when you want to hide a design from YOUR server specifically
   without editing the mod. Matching is case-insensitive. Restart the
   server to apply changes.

   {
       "BlockedDesigns": ["Dead Teddy", "Crow"]
   }


2. BlockedPacks  (skip an entire sideload pack, not a lock)
   Top-level array of pack IDs. Listed packs are skipped during the pack
   merge step on startup — none of their designs, categories, tags, item
   name overrides, or variant colours are loaded into the server catalogue.
   Approved packs still installed on disk are simply ignored.

   Use this when you have a pack PBO loaded (because another mod or the
   modpack requires it) but don't want its contents on your server. Saves
   listing every pack design individually under BlockedDesigns. Pack IDs
   are case-sensitive and must match the PackID exactly (see server log
   line "[SprayZ] Pack pending: <PackID>" on boot).

   {
       "BlockedPacks": ["SprayZ_Pack_DayZRP"]
   }


3. DiscoveryLockedDesigns  (lock until inspected in the wild)
   Top-level array of design names. Listed designs are hidden from the
   picker until the player inspects another player's graffiti of that
   design (F key). Once discovered, the design unlocks permanently for
   that player (or character, in per-character mode).

   {
       "DiscoveryLockedDesigns": ["Pentagram", "Star"]
   }


4. QuestRequirements  (lock behind Expansion quest completion)
   Array of entries in SprayZ_Designs.json. Each entry locks one or more
   designs until the specified Expansion quest is completed.

   {
       "QuestRequirements": [
           {
               "RequiredQuestID": 300,
               "DesignNames": ["Star", "Pentagram"],
               "LockedMessage": "Complete 'Street Art Initiation' to unlock.",
               "QuestLockOnly": true
           }
       ]
   }

   Fields:
     RequiredQuestID  Expansion quest ID that unlocks the designs on completion
     DesignNames      Array of design names to lock behind this quest
     LockedMessage    UI message shown to locked players trying to select it
     QuestLockOnly    true  = quest completion is the ONLY way to unlock
                      false = dual-unlock; quest OR inspection-discovery both work

   DUAL UNLOCK: Set "QuestLockOnly": false to make the quest one of two
   unlock paths — players can either finish the quest or inspect the design
   in the wild. Useful for optional reward quests where you don't want to
   gate the design behind a single path.

   QuestRequirements requires EnableQuestRequirements = true in
   SprayZ_Config.json. Otherwise it is ignored.


=====================================================
  CATEGORIES AND TAGS (for DesignCategories / DesignTags filters)
=====================================================

Built-in categories (source: SprayZ_DesignHelper.GetDesignCategory and
SprayZ_DesignPickerUI.BuildCategoryMap — both must agree):

  "Plants"    Roses and flowers
  "Phrases"   Stylized text designs (Love Text, etc.)
  "Symbols"   Icons (Heart, Peace, Star, Arrows, etc.)
  "Cats"      Cat designs (Scared Cat, Third Eye Cat, Cat Tongue, etc.)
  "Food"      Food items (Pizza, Strawberry)
  "Letters"   Alphabet designs (programmatic — A1 White, B2 Red, etc.)
  "Flags"     Flag designs

Built-in tags (source: SprayZ_DesignHelper.GetDesignTags):

  "hostile"         Aggressive designs (Bomb, Grim Reaper, X Mark, Dagger,
                    Snake, Thumbs Down, hostile weapon designs, etc.)
  "friendly"        Positive designs (Heart, Heart Wings, Peace,
                    Thumbs Up, Soft Heart, Angel Heart, etc.)
  "directional"     Navigation (Arrow Up/Down/Left/Right, Bullseye, Warning Sign)
  "assault_rifle"   Gun AK, Gun M4, AUG, Famas, FAL, M16
  "rifle"           Sniper Rifle, Repeater, Mosin, SVD, SKS
  "marksman_rifle"  VAL, VSS
  "smg"             Bizon, P90, UMP45, Uzi
  "pistol"          DEAGLE, Longhorn, Revolver
  "shotgun"         Pump Shotgun
  "launcher"        RPG, M79
  "explosive"       Bomb, Dynamite, Grenade, RPG, M79
  "melee"           Baseball Bat, Crowbar, Katana, Machete, Sledgehammer
  "lmg"             PKM

Pack mods can contribute additional categories and tags for their own
designs. Those overlay on top of the built-in lists and are visible to
DesignCategories / DesignTags filters automatically.


=====================================================
  QUICK EXAMPLES
=====================================================

--- Simple: spray 5 graffiti anywhere (no SprayZ filter needed) ---

Objective_A_500.json:
  { "ID": 500, "ObjectiveType": 10, "ObjectiveText": "Spray 5 graffiti",
    "ActionNames": ["SprayZ_ActionSprayGraffiti"], "ExecutionAmount": 5 }


--- Medium: spray Pentagram 3 times near NWAF ---

Objective_A_501.json:
  { "ID": 501, "ObjectiveType": 10, "ObjectiveText": "Spray Pentagram near NWAF",
    "ActionNames": ["SprayZ_ActionSprayGraffiti"], "ExecutionAmount": 3 }

SprayZ_Designs.json filter:
  { "ObjectiveID": 501, "ActionType": "spray", "DesignName": "Pentagram",
    "Position": [4500, 340, 10200], "MaxDistance": 200 }


--- Complex: night raid on enemy base, hostile tag, indoors, glow can ---

Objective_A_502.json:
  { "ID": 502, "ObjectiveType": 10,
    "ObjectiveText": "Spray 3 hostile designs inside an enemy base at night in the rain",
    "ActionNames": ["SprayZ_ActionSprayGraffiti"], "ExecutionAmount": 3 }

SprayZ_Designs.json filter:
  { "ObjectiveID": 502, "ActionType": "spray",
    "DesignTags": ["hostile"], "TerritoryMode": "enemy",
    "TimeOfDay": "night", "WeatherCondition": "rain", "Exposure": "indoor",
    "CanType": "glow" }


--- Spraydex: inspect any 50 different designs ---

Objective_A_503.json:
  { "ID": 503, "ObjectiveType": 10,
    "ObjectiveText": "Discover 50 unique graffiti designs",
    "ActionNames": ["SprayZ_ActionSprayGraffiti"], "ExecutionAmount": 50 }

SprayZ_Designs.json filter:
  { "ObjectiveID": 503, "ActionType": "discover_unique" }


--- Spell: spray H-E-L-L-O left-to-right on a wall, any font/color ---

Objective_A_504.json:
  { "ID": 504, "ObjectiveType": 10,
    "ObjectiveText": "Spell HELLO across a wall",
    "ActionNames": ["SprayZ_ActionSprayGraffiti"], "ExecutionAmount": 5 }

SprayZ_Designs.json filter:
  { "ObjectiveID": 504, "ActionType": "spray_spell",
    "DesignSequence": ["H", "E", "L", "L", "O"] }

  Single-character entries are alphabet shorthand — they match any font and
  any color of that letter. So the player can spray H1 Red, E3 Blue,
  L2 White, L1 Orange, O3 Pink and it still counts.

  Placement is also enforced: each letter must be to the right of the
  previous one along the wall (within 0.5m vertical). Wrong letter or wrong
  direction resets the sequence.

  To require a specific color throughout, use color shorthand like
  "H White" (any font, White only). To require a specific font+color,
  use the full design name like "H1 White".

#   PART 2 - FILTER REFERENCE
#####################################################


================================================================================
  1. OVERVIEW
================================================================================

Each entry in the "QuestObjectiveFilters" array in SprayZ_Designs.json links an
Expansion quest objective (by ObjectiveID) to a SprayZ action type with optional
filters. When a player performs the matching action, the filter is checked —
if ALL conditions pass the objective increments.

Minimal example (spray anything, anywhere):

    {
        "ObjectiveID": 3000,
        "ActionType": "spray"
    }

Everything else is optional and defaults to "no restriction" when omitted.


================================================================================
  2. ACTION TYPE REFERENCE (11 TYPES)
================================================================================

SPRAY FAMILY (player sprays graffiti):
  spray            Spray graffiti. The basic "go spray something" action.
  spray_over       Spray on top of existing graffiti (paint over it).
  spray_match      Spray a design that matches nearby graffiti.
  spray_sequence   Spray specific designs in a specific order.
  spray_chain      Each new spray must be within range of the previous one.
  spray_spell      Like spray_sequence but also enforces left-to-right wall
                   placement with a vertical tolerance of 0.5m. Used for
                   spelling out words with alphabet designs.
  mark             Spray at spread-out locations (each spray far from all
                   other marks placed for this objective).

CLEAN FAMILY (player cleans graffiti):
  clean            Clean/remove graffiti using a wet sponge.

DISCOVER FAMILY (player inspects graffiti with the F key):
  discover         Inspect graffiti (any matching filter).
  discover_unique  Inspect graffiti; each discovery for this objective must
                   be a DIFFERENT design than the previous discoveries for
                   the same objective.
  discover_player  Inspect graffiti belonging to a specific player
                   (by UID or name).


================================================================================
  3. PARAMETER REFERENCE (A-Z)
================================================================================

--------------------------------------------------------------------------------
ActionType
--------------------------------------------------------------------------------
  Type:     string (required)
  Default:  "spray"
  Used by:  ALL

  Determines which validator runs. Must be one of the 11 values listed above.

    "ActionType": "clean"


--------------------------------------------------------------------------------
CanType
--------------------------------------------------------------------------------
  Type:     string
  Default:  'empty' (any)
  Used by:  all spray types, mark

  Restricts which spray can / size the player must use. Size is cycled at
  spray time via the T key (Small -> Medium -> Large). Accepts keywords:

    'empty'         Any spray can / size
    "small"    Player must press T to small before spraying
    "medium"   Player must be on medium (default)
    "large"    Player must press T to large before spraying
    "glow"     Glow can (any size)
    "noglow"   Non-glow can (any size)
    (exact)    Exact class name. Targets one specific can. Examples:
                 "SprayZ_GraffitiCan"             (base, non-glow)
                 "SprayZ_GraffitiCanGlow"         (base, glow)
                 "SprayZ_GraffitiCan_Dusk"        (Dusk skin, non-glow)
                 "SprayZ_GraffitiCanGlow_Tempest" (Tempest skin, glow)
               Available skins: Feral, Orbit, Watcher, Visitor, Risen,
               Behemoth, Ronin, Titan, Dusk, Tempest, Rust. Each ships
               in glow + non-glow variants.

  Does NOT apply to: clean, discover family


--------------------------------------------------------------------------------
CleanTarget
--------------------------------------------------------------------------------
  Type:     string
  Default:  "any"
  Used by:  clean

  Whose graffiti must be cleaned:

    "any"      Any graffiti
    "own"      Only the player's own graffiti
    "others"   Only other players' graffiti (not own)
    "enemies"  Only enemy players' graffiti (requires territory module)
    "allies"   Only allied players' graffiti (requires territory module)

  Ally/enemy is decided by Expansion territory membership: "enemies" means
  the owner is NOT a member of any territory the cleaner belongs to, and
  "allies" means they share at least one territory.


--------------------------------------------------------------------------------
DesignCategories
--------------------------------------------------------------------------------
  Type:     array of strings
  Default:  [] (any)
  Used by:  ALL

  Restricts the objective to designs in specific categories (OR logic — the
  design must be in at least one of the listed categories). Built-in values:
  "Plants", "Phrases", "Symbols", "Cats", "Food", "Letters", "Flags".
  Pack mods may add more.

    "DesignCategories": ["Plants", "Cats"]


--------------------------------------------------------------------------------
DesignName
--------------------------------------------------------------------------------
  Type:     string
  Default:  'empty' (any)
  Used by:  spray, spray_over, spray_chain, mark, clean, discover, discover_unique

  Restricts the objective to one specific design by exact case-sensitive name
  as it appears in SprayZ_Designs.json.

    "DesignName": "Red Rose"

  For spray-family: the sprayed design must match.
  For clean: the cleaned graffiti's design must match.
  For discover: the inspected graffiti's design must match.

  Does NOT apply to: spray_sequence / spray_spell (use DesignSequence),
                     spray_match (matches nearby graffiti),
                     discover_player (filters by player, not design)


--------------------------------------------------------------------------------
DesignSequence
--------------------------------------------------------------------------------
  Type:     array of strings
  Default:  [] (empty)
  Used by:  spray_sequence, spray_spell

  Ordered list of design "slots" that must be filled in order. Spraying a
  design that doesn't satisfy the current slot resets the player's progress
  for this objective back to 0.

  Each entry can be in one of four forms (most specific to least):

    FULL NAME       "H1 White"   Exactly this one design. No wildcards.
    CHAR + COLOR    "H White"    Any font of H, but only the White color.
    CHAR + FONT     "H1"         Font 1 of H, any of the 9 alphabet colors.
    CHAR ONLY       "H"          Any H — any font, any color.

  Matching rule: exact name takes priority. If the sprayed design matches the
  entry literally, it counts. Otherwise the entry is parsed as alphabet
  shorthand (char [+ font] [+ color]) and compared against the sprayed
  design's alphabet metadata.

  Valid shorthand characters: A-Z, 0-9, !, ?. Valid fonts: 1, 2, 3. Valid
  colors (alphabet colors only): White, Black, Blue, Green, Orange, Pink,
  Purple, Red, Yellow.

  Shorthand only matches alphabet designs — entries like "Red Rose" will
  always fall through to literal matching. There are no regular designs in
  the catalogue with single-character names, so "H"/"!"/"3" shorthand is
  unambiguous.

    "DesignSequence": ["H", "E", "L", "L", "O"]

  matches HELLO spelled with any mix of fonts and colors.

    "DesignSequence": ["H White", "E White", "L White", "L White", "O White"]

  matches HELLO in White, mixed fonts allowed.

    "DesignSequence": ["H1 White", "E2 White", "L3 White", "L1 White", "O2 White"]

  requires that exact per-letter font + color combination.

  For spray_spell: additionally enforces left-to-right placement along the
  wall the first spray landed on. Each subsequent spray must be offset in
  the "right" direction of the wall surface normal, with vertical delta
  <= 0.5m. Right direction is computed as rotate(normal, 90deg) in the XZ
  plane — it is wall-relative, not camera-relative.

  The Expansion objective's ExecutionAmount should equal the array length.


--------------------------------------------------------------------------------
DesignTags
--------------------------------------------------------------------------------
  Type:     array of strings
  Default:  [] (any)
  Used by:  ALL

  Restricts the objective to designs with at least one of the listed tags
  (OR logic). Built-in tags: "hostile", "friendly", "directional". Pack mods
  may add more.

    "DesignTags": ["hostile"]

  DesignCategories and DesignTags are checked independently — you can use
  both on the same filter.


--------------------------------------------------------------------------------
DiscoverTarget
--------------------------------------------------------------------------------
  Type:     string
  Default:  "any"
  Used by:  discover, discover_unique, discover_player

  Controls whose graffiti must be inspected (by ally/enemy status):

    "any"      Any other player's graffiti
    "enemies"  Enemy players only
    "allies"   Allied players only

  Players can never "discover" their own graffiti — it's always someone
  else's, by design.


--------------------------------------------------------------------------------
Exposure
--------------------------------------------------------------------------------
  Type:     string
  Default:  'empty' (any)
  Used by:  ALL

  Restricts the action based on sky exposure:

    'empty'         Any
    "outdoor"  Must be exposed to the sky (raycast straight up passes)
    "indoor"   Must NOT be exposed to the sky


--------------------------------------------------------------------------------
MatchMode
--------------------------------------------------------------------------------
  Type:     string
  Default:  "exact"
  Used by:  spray_match

  How to compare the player's spray with nearby existing graffiti found
  within SprayMatchRadius:

    "exact"     The sprayed design must be identical to the nearby one
    "category"  The sprayed design must share a category with the nearby one


--------------------------------------------------------------------------------
MaxDistance
--------------------------------------------------------------------------------
  Type:     float (meters)
  Default:  0 (disabled)
  Used by:  ALL (paired with Position)

  Maximum distance from Position. Only checked when both Position is non-
  zero AND MaxDistance > 0.

    "MaxDistance": 200


--------------------------------------------------------------------------------
MaxElevation / MinElevation
--------------------------------------------------------------------------------
  Type:     float (world Y, meters)
  Default:  0 (disabled)
  Used by:  ALL

  Min/max Y coordinate band the action must fall within. Each value is only
  checked when > 0, so you can use one without the other.

    "MinElevation": 300,
    "MaxElevation": 500


--------------------------------------------------------------------------------
MinSprayDistance
--------------------------------------------------------------------------------
  Type:     float (meters)
  Default:  0 (disabled)
  Used by:  mark

  Minimum distance between each mark and every previous mark for the same
  objective. Every new spray is compared against the full list of prior
  marks — closer than this distance and it doesn't count (but it also
  doesn't reset progress).

    "MinSprayDistance": 500


--------------------------------------------------------------------------------
ObjectiveID
--------------------------------------------------------------------------------
  Type:     int (required)
  Default:  -1
  Used by:  ALL

  The ID of the Expansion objective this filter applies to. Must match the
  "ID" field in Objective_A_<ID>.json.

    "ObjectiveID": 3000


--------------------------------------------------------------------------------
Position
--------------------------------------------------------------------------------
  Type:     vector [x, y, z]
  Default:  [0, 0, 0] (disabled)
  Used by:  ALL (paired with MaxDistance)

  World-space center point for distance-based filtering. Pair with
  MaxDistance — either one alone does nothing.

    "Position": [4500.0, 340.0, 10200.0]

  Use 0.0 for Y if you only care about horizontal distance.


--------------------------------------------------------------------------------
RequireUnique
--------------------------------------------------------------------------------
  Type:     bool
  Default:  false
  Used by:  spray

  When true, each spray for this objective must use a different design than
  the player's previous sprays for the same objective. Repeat sprays don't
  count but don't reset progress.

  For "discover a different design each time" use discover_unique instead —
  that's a separate action type with uniqueness built in.


--------------------------------------------------------------------------------
SprayChainMaxDistance
--------------------------------------------------------------------------------
  Type:     float (meters)
  Default:  0 (disabled)
  Used by:  spray_chain

  Maximum distance between consecutive sprays. Each new spray must be within
  this distance of the previous spray for the same objective. The first
  spray always counts.

    "SprayChainMaxDistance": 50


--------------------------------------------------------------------------------
SprayOverDesign
--------------------------------------------------------------------------------
  Type:     string
  Default:  'empty' (any)
  Used by:  spray_over

  The specific design name of the existing graffiti that must be sprayed
  over. Empty means any existing graffiti qualifies (subject to
  SprayOverTarget).

    "SprayOverDesign": "X Mark"


--------------------------------------------------------------------------------
SprayOverRadius
--------------------------------------------------------------------------------
  Type:     float (meters)
  Default:  1.0
  Used by:  spray_over

  Search radius for finding nearby existing graffiti that the new spray
  must be painting OVER.

    "SprayOverRadius": 2.0


--------------------------------------------------------------------------------
SprayMatchRadius
--------------------------------------------------------------------------------
  Type:     float (meters)
  Default:  5.0
  Used by:  spray_match

  Search radius for finding nearby existing graffiti that the new spray
  must MATCH (by exact design or category, see MatchMode). Separate from
  SprayOverRadius so spray_match can use a more generous "in the same
  area" feel without affecting spray_over.

    "SprayMatchRadius": 5.0


--------------------------------------------------------------------------------
SprayOverTarget
--------------------------------------------------------------------------------
  Type:     string
  Default:  "any"
  Used by:  spray_over

  Whose existing graffiti must be sprayed over:

    "any"      Any graffiti
    "enemies"  Only enemy players' graffiti (requires territory module)
    "allies"   Only allied players' graffiti (requires territory module)


--------------------------------------------------------------------------------
SurfaceType
--------------------------------------------------------------------------------
  Type:     string
  Default:  'empty' (any)
  Used by:  all spray types, mark, clean, discover family

  Restricts the action by what kind of surface the graffiti is on:

    'empty'        Any surface
    "wall"    Only wall-mounted graffiti (surface normal Y > 0.7 at placement)
    "ground"  Only ground-mounted graffiti (placed with ground SurfaceY flow)

  For spray: checked against the surface normal of the new placement.
  For clean: checked against the IsGround flag of the cleaned graffiti,
             captured before removal (so the filter still resolves after
             the record is deleted from persistence).
  For discover: checked against the IsGround flag of the inspected graffiti.


--------------------------------------------------------------------------------
TargetPlayerName
--------------------------------------------------------------------------------
  Type:     string
  Default:  'empty' (disabled)
  Used by:  discover_player

  In-game name of the player whose graffiti must be inspected. Use as a
  fallback or alongside TargetPlayerUID — if both are set, either can match.

    "TargetPlayerName": "GraffitiDave"


--------------------------------------------------------------------------------
TargetPlayerUID
--------------------------------------------------------------------------------
  Type:     string
  Default:  'empty' (disabled)
  Used by:  discover_player

  Steam UID of the player whose graffiti must be inspected. More reliable
  than TargetPlayerName since names can change.

    "TargetPlayerUID": "76561198012345678"


--------------------------------------------------------------------------------
TerritoryMode
--------------------------------------------------------------------------------
  Type:     string
  Default:  "any"
  Used by:  ALL (spray family, mark, clean, discover family)

  Requires the action to be performed in a territory of the specified
  ownership. Uses Expansion BaseBuilding territories.

    "any"     No territory restriction
    "own"     Inside the player's own territory (a flag they're a member of)
    "enemy"   Inside a territory the player is NOT a member of
    "none"    Outside any territory entirely

  Note: there is no "ally" option. Ally/enemy semantics live in CleanTarget,
  SprayOverTarget, and DiscoverTarget — TerritoryMode only cares about
  whether the ACTING player is a member of the territory at the action
  position.

  Requires the Expansion BaseBuilding module. Without it, CheckTerritory
  always returns "none" and only "any" / "none" modes will ever match.


--------------------------------------------------------------------------------
TimeOfDay
--------------------------------------------------------------------------------
  Type:     string
  Default:  'empty' (any)
  Used by:  ALL

  Restricts the action by time of day:

    'empty'       Any time
    "day"    Must be daytime
    "night"  Must be nighttime

  Day/night boundaries come from SprayZ_Config.json NightStartHour and
  NightEndHour (defaults: 20:00 - 05:00 = night).


--------------------------------------------------------------------------------
WeatherCondition
--------------------------------------------------------------------------------
  Type:     string
  Default:  'empty' (any)
  Used by:  ALL

  Restricts the action by weather:

    'empty'       Any
    "rain"   Rain intensity >= 0.3
    "clear"  Rain intensity <  0.3


================================================================================
  4. SHARED / ENVIRONMENTAL FILTERS
================================================================================

These apply to ALL action types and combine freely (AND logic):

  - TimeOfDay         (day / night)
  - WeatherCondition  (rain / clear)
  - Exposure          (indoor / outdoor)
  - MinElevation      (float, world Y)
  - MaxElevation      (float, world Y)
  - Position + MaxDistance  (radial)
  - DesignCategories  (array of category names)
  - DesignTags        (array of tag names)
  - TerritoryMode     (any / own / enemy / none)
  - SurfaceType       (wall / ground; applies to all action types)

Example combining several:

    "TimeOfDay": "night",
    "WeatherCondition": "rain",
    "Exposure": "outdoor",
    "MinElevation": 200,
    "SurfaceType": "wall"

================================================================================
  NOTES
================================================================================

- String values are case-sensitive. "spray" not "Spray"; "Red Rose" not
  "red rose".

- Omitted parameters use their defaults. You only need to set the ones you
  want to filter on.

- Multiple filters on one entry are AND logic — ALL conditions must pass.
  Inside DesignCategories and DesignTags, array items are OR logic (the
  design needs to match any one entry in the list).

- For spray_sequence / spray_spell, the Expansion objective's
  ExecutionAmount should equal DesignSequence.Count().

- Discovery actions never match the inspecting player's own graffiti.

- TerritoryMode, CleanTarget "enemies" / "allies", SprayOverTarget, and
  DiscoverTarget all require the Expansion BaseBuilding module. Without
  it, territory checks silently return "none" and those modes will not
  match anything except "any".

- Spell sequence direction is wall-relative: "right" is computed from the
  first spray's surface normal via a 90 degree XZ rotation. It is NOT
  camera-relative — strafing past the wall doesn't trick it.
